# TrueAlpha

[![CI](https://github.com/AdamFehmoun/TrueAlpha/actions/workflows/ci.yml/badge.svg)](https://github.com/AdamFehmoun/TrueAlpha/actions/workflows/ci.yml)

Quantitative research on daily crypto data, built around one rule: **no unverified
claims**. Every number in this README is generated by a script from hash-pinned data,
and CI fails if any of it drifts.

## The contract

1. **Reproducible data.** OHLCV is downloaded with **absolute dates** (never relative
   ranges), stored as parquet next to a `manifest.json` recording source, dates,
   download time, and the SHA-256 of the data content. Every load re-verifies the hash;
   a dedicated test fails on any mismatch. If the exchange ever restates history, the
   guardrail fails loudly instead of silently changing results.
2. **No leakage by construction.** Train/test splits are temporal only (no shuffling),
   with purge and embargo. `engine.splits.assert_no_leakage` rejects overlapping,
   shuffled, or insufficiently gapped splits — and the tests for it were written before
   any model exists in this repo.
3. **Backtest correctness is tested, not assumed.** The engine must reproduce
   buy & hold as the asset's gross return net of the entry fee *exactly*
   (`tests/test_buy_and_hold_identity.py`), on synthetic and on real data. Every metric
   has a unit test against hand-computed values. Two additional oracles close the loop:
   a distributional recovery test (known Sharpe/vol from 200k synthetic i.i.d. returns,
   tolerance derived from sampling error) and an independent cross-check of the whole
   engine against vectorbt on identical data and conventions.
4. **No hand-written numbers.** The results section below is generated by
   `scripts/generate_results.py`; CI fails if the README and the data disagree.

## Assumptions (all of them)

| Assumption | Value |
|---|---|
| Universe | BTC/USDT, ETH/USDT — Binance spot via ccxt |
| Period | 2022-01-01 → 2024-12-31 (UTC, inclusive), daily candles |
| Execution | Signal computed at close[t], filled at open[t+1] — zero look-ahead |
| Mark-to-market | At each next open; final bar at its close |
| Fees | 10 bps per trade, applied to traded notional |
| Slippage | 0 bps by default, parameterizable (`BacktestConfig.slippage_bps`) |
| Position sizing | Signal = target weight of equity; baselines are long/flat, no leverage |
| MA crossover convention | Signal ∈ {0, 1} = **long-only** (long/flat); a long/short variant would use {−1, +1} |
| Annualization | √365 (crypto trades every calendar day) |
| Risk-free rate | **0** — Sharpe, Sortino and t-stat are computed on raw returns, with no excess-return adjustment |
| Not modeled | Funding, borrow costs, market impact beyond the slippage parameter |

These are **full-sample descriptive statistics of trivial baselines** (no parameters

## Reproduce everything

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

python -m data.download              # re-download; hashes must match manifest.json
pytest                               # repro + anti-leakage + identity + metric tests
python -m scripts.generate_results   # regenerate the results table above
```

## Repository layout

```
data/         reproducible download (absolute dates), SHA-256 manifest, verified loader
engine/       temporal splits w/ purge+embargo, vectorized backtest, tested metrics
strategies/   baselines: buy & hold, MA crossover 20/50 long-only — signal = f(past closes)
tests/        the guardrails; written before any strategy sophistication
scripts/      generate_results.py — the only source of numbers in this README
notebooks/    exploration only; nothing in a notebook is a result
```

## Guardrails enforced in CI

- `ruff check` + `ruff format --check`
- `mypy --strict`
- `pytest`: data-hash reproducibility, anti-leakage validator, buy&hold identity,
  per-metric unit tests, strategy causality tests
- Synthetic-recovery oracle: the engine + √365 annualization must recover a KNOWN
  (Sharpe, vol) from 200k i.i.d. synthetic returns, within a tolerance derived from
  sampling error (`tests/test_synthetic_recovery.py`)
- Independent engine cross-check: buy & hold and the MA crossover must produce the
  same Sharpe / total return / max drawdown / trade count as vectorbt on identical
  data, execution timing and fees (`tests/test_vectorbt_crosscheck.py`)
- README sync: `python -m scripts.generate_results --check`
