# TrueAlpha

[![CI](https://github.com/AdamFehmoun/TrueAlpha/actions/workflows/ci.yml/badge.svg)](https://github.com/AdamFehmoun/TrueAlpha/actions/workflows/ci.yml)

Quantitative research on daily crypto data, built around one rule: **no unverified
claims**. Every number in this README is generated by a script from hash-pinned data,
and CI fails if any of it drifts.

## The contract

1. **Reproducible data.** OHLCV is downloaded with **absolute dates** (never relative
   ranges), stored as parquet next to a `manifest.json` recording source, dates,
   download time, and the SHA-256 of the data content. Every load re-verifies the hash;
   a dedicated test fails on any mismatch. If the exchange ever restates history, the
   guardrail fails loudly instead of silently changing results. Calendars are verified
   on every load too: daily data must be gap-free; hourly data may have
   exchange-maintenance holes, each one **pinned by timestamp** in the manifest
   (`missing_bars`) — an unpinned hole fails loudly and is listed, and pinned holes
   **stay holes**: no bar is ever interpolated, no return is ever invented.
2. **No leakage by construction.** Train/test splits are temporal only (no shuffling),
   with purge and embargo. `engine.splits.assert_no_leakage` rejects overlapping,
   shuffled, or insufficiently gapped splits — and the tests for it were written before
   any model exists in this repo.
3. **Backtest correctness is tested, not assumed.** The engine must reproduce
   buy & hold as the asset's gross return net of the entry fee *exactly*
   (`tests/test_buy_and_hold_identity.py`), on synthetic and on real data. Every metric
   has a unit test against hand-computed values. Two additional oracles close the loop:
   a distributional recovery test (known Sharpe/vol from 200k synthetic i.i.d. returns,
   tolerance derived from sampling error) and an independent cross-check of the whole
   engine against vectorbt on identical data and conventions.
4. **No hand-written numbers.** The results sections below are generated by
   `scripts/generate_results.py`; CI fails if the README and the data disagree. The
   same script writes [`results/metrics.json`](results/metrics.json) — every number at
   **full float precision**, committed, and asserted **byte-for-byte with zero
   tolerance** by `tests/test_metrics_golden.py`: a single float that moves anywhere
   breaks the build.

## Assumptions (all of them)

| Assumption | Value |
|---|---|
| Universe | BTC/USDT, ETH/USDT — Binance spot via ccxt |
| Period | 2017-08-17 → 2026-06-30 (UTC, inclusive), daily candles |
| Hourly data | Same symbols and absolute span in 1h bars, hash-pinned in `manifest.json` for the next milestone — bar counts and pinned holes live in the manifest and `results/metrics.json` (never hand-written here), and **no number below uses them yet** |
| Hourly gaps | Missing bars (exchange maintenance) are **kept as holes**, pinned by timestamp in the manifest (`missing_bars`); the loader fails loudly and lists any unpinned hole; nothing is ever interpolated |
| Execution | Signal computed at close[t], filled at open[t+1] — zero look-ahead |
| Mark-to-market | At each next open; final bar at its close |
| Fees | 10 bps per trade, applied to traded notional |
| Slippage | 0 bps by default, parameterizable (`BacktestConfig.slippage_bps`) |
| Position sizing | Signal = target weight of equity; baselines are long/flat, no leverage |
| MA crossover convention | Signal ∈ {0, 1} = **long-only** (long/flat); a long/short variant would use {−1, +1} |
| Annualization | √(bars per year), driven by the `timeframe` field of `manifest.json`: √365 for 1d bars, √8760 for 1h bars (`engine.metrics.BARS_PER_YEAR` — crypto trades every calendar day) |
| t-stat `n_years` | **Bar-count convention:** `n_years = n_bars / (365.25 × bars per day)` — a 365.25-day calendar year applied to the bar *count*, not the real index span (`engine.metrics.sharpe_tstat`) |
| Sharpe error bar | Lo (2002) SE of the annualized Sharpe under **i.i.d.-normal** returns ≈ 1/√(years of sample) — depends **only on the calendar span**, not the sampling frequency: hourly bars would not shrink it. Serial dependence (long/flat persistence) **widens** the true SE — conservative for a no-edge conclusion, not for declaring significance (`engine.metrics.sharpe_standard_error`) |
| Risk-free rate | **0** — Sharpe, Sortino and t-stat are computed on raw returns, with no excess-return adjustment |
| Not modeled | Funding, borrow costs, market impact beyond the slippage parameter |

**Hole policy for evaluation (decided 2026-07-26, before M3's hourly walk-forward
runs into it):** the walk-forward validator is **calendar-aware** and consumes the
manifest's pinned `missing_bars` as a **whitelist** — generated by
`python -m data.download`, cross-checked against the hashed data by the loader in
both directions, never edited by hand. A window whose calendar gaps are ALL
whitelisted is accepted: the position is held across the hole and the pre-hole bar
is marked at the next available open — real market movement, **no bar interpolated,
no return invented**, so "holes stay holes" remains literally true. Any calendar gap
NOT in the whitelist still fails loudly, listed by timestamp, and positionally
gapped (hand-built) windows are rejected unconditionally. Chosen over full-grid
reindexation (the rejected option 2) because reindexation fabricates rows whose
"flat, zero-return, zero-cost" semantics are an invention the data does not
contain. On the gap-free daily data the whitelist is empty and provably changes
nothing (`test_hole_whitelist_mechanism_leaves_gap_free_results_bit_identical` +
the byte-identical golden).

## Out-of-sample evaluation — walk-forward (auto-generated)

The block between the markers below is generated by the same script as the table
above; CI fails if it drifts. What makes the word "OOS" honest here (implemented and
documented in `engine/evaluate.py`):

- **The signal is causal** — `signal[t]` uses bars ≤ t only, proven by
  `test_signal_is_causal`. Bars *before* a test window feed the strategy's look-back
  (an MA(200) needs 200 bars of history): that is a look-back window, **not**
  leakage.
- **Parameter selection sees train only.** For each fold, every grid candidate is
  backtested on a price history truncated at the end of train, and the argmax picks
  one parameter set per fold. `test_selection_is_blind_to_test_window` proves that
  perturbing anything after a fold's train changes none of its selected parameters.
- **Measurement sees test only.** The per-fold winner runs on the test region,
  spliced by segments: consecutive folds that select IDENTICAL parameters run as
  ONE continuous backtest — the position carries over the fold boundary, so the
  boundary adds no artificial flat bar and no phantom re-entry fee
  (`test_adjacent_folds_splice_exactly` pins concatenated fold returns against a
  single union backtest at 1e-12) — and a real parameter change restarts flat
  (re-allocating is actual behavior, `test_param_change_resets_position_to_flat_between_folds`).
  `test_fold_test_returns_ignore_future_bars` proves that truncating the series
  after a test window changes nothing, bit-for-bit, except the marking of that
  window's final bar (close vs next open), which the test pins analytically.
- **`assert_no_leakage` runs inside the pipeline** for every fold — not only in the
  test suite (DoD criterion 4: an evaluation must *pass* the validator, not merely
  coexist with it).

### Coverage convention (locked 2026-07-27, before any model)

Published Sharpe and t-stat are computed on **all OOS bars, flat bars included as
zero returns**, because that is the actually investable series. `time_in_market`
and `n_bars_exposed` are published next to them (README and `metrics.json`,
engine-counted) so any reader can recompute the exposed-only variant. Given once,
on the current runs (example numbers refreshed 2026-07-28 with the B4 span; the
convention itself is unchanged and stays locked): ETH's
Sharpe −0.3118 on all 648 bars becomes **−0.4151** on
its 313 exposed bars (33% larger in magnitude) while its t-stat barely moves
(−0.415 → −0.384); BTC: 0.8187 → 1.1549, t 1.090 → 1.119. The
"indistinguishable from zero" verdict is **unchanged**: the convention moves the
Sharpe, not the verdict. Why this is locked now, before any model exists: a model
that trades less often would be flattered or punished by this choice — left
unwritten, the convention becomes a degree of freedom. This is the same rule as
"the anti-leakage validator is written before the model", not a presentation
preference.

## Guardrails enforced in CI

- `ruff check` + `ruff format --check`
- `mypy --strict`
- `pytest`: data-hash reproducibility, anti-leakage validator, buy&hold identity,
  per-metric unit tests, strategy causality tests, frequency-safe annualization pins
  (default √365 by name, hourly t-stat coherence), hourly calendar integrity (every
  hole pinned and listed, never filled)
- Synthetic-recovery oracle: the engine + √365 annualization must recover a KNOWN
  (Sharpe, vol) from 200k i.i.d. synthetic returns, within a tolerance derived from
  sampling error (`tests/test_synthetic_recovery.py`)
- Independent engine cross-check: buy & hold and the MA crossover must produce the
  same Sharpe / total return / max drawdown / trade count as vectorbt on identical
  data, execution timing and fees (`tests/test_vectorbt_crosscheck.py`)
- Walk-forward OOS protocol: `assert_no_leakage` runs inside `engine.evaluate` for
  every fold, and two blindness invariants are enforced — selection blind to the
  test window, measurement blind to future bars
  (`tests/test_walk_forward_evaluate.py`). The blindness test carries an
  **anti-vacuity guard**: its two-regime fixture makes the argmax provably move
  between folds (at least two distinct parameter sets), so the invariant cannot be
  green by vacuity. Fold boundaries are pinned by `test_adjacent_folds_splice_exactly`
  (same params ⇒ exact splice), by `n_carried_boundaries` (engine-counted, published,
  asserted to be exactly 1 per symbol and configuration on the 1d runs), and by the
  hole discipline (unknown calendar gaps rejected and listed; whitelisted holes stay
  holes). The uncertainty machinery is pinned by Lo-SE tests (`tests/test_metrics.py`)
- Golden metrics: `results/metrics.json` is regenerated in memory and compared
  **byte-for-byte on raw bytes, zero tolerance** (`tests/test_metrics_golden.py`) —
  any float that moves fails the build with instructions to regenerate and commit
  the diff. Bit-for-bit is pinned to the prescribed Linux x86-64/glibc environment
  (the CI image and WSL); another platform's libm may round `**` (cagr) 1 ulp
  differently and fail the golden test loudly — by design, never silently
- README + golden sync: `python -m scripts.generate_results --check` verifies the
  README **and** `results/metrics.json`
